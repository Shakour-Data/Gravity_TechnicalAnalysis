SECURITY PRACTICES / INSTRUCTIONS
- NEVER commit secrets in plaintext. If a secret is accidentally committed, rotate it immediately.
- Use a secrets manager (Vault/AWS/Azure) and grant services access using ephemeral credentials or IAM roles.
- Apply least privilege: create separate DB user for the application with only required permissions.
- Use TLS for all network communication between services.
- Rotate keys and credentials regularly and after personnel changes.
- Audit logs: enable DB, auth, and deploy audit logs.
- Use strong random secrets (e.g., `openssl rand -hex 32` for 256-bit keys).
