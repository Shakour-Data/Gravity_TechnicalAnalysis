
# پرامپت جامع و تخصصی برای پروژه Gravity_TechnicalAnalysis

این راهنما برای یک دستیار هوشمند تخصصی (AI Agent) طراحی شده تا بتواند پروژه را از نظر فنی، مفهومی، یادگیری ماشین و تحلیل تکنیکال به طور کامل مدیریت و توسعه دهد.

---

## هدف و معماری پروژه
Gravity_TechnicalAnalysis یک سرویس تحلیل تکنیکال و یادگیری ماشین برای بازارهای مالی است که داده‌های خام را جمع‌آوری، تحلیل و نتایج را از طریق API و WebSocket ارائه می‌دهد. ساختار پروژه:

- **دیتابیس PostgreSQL**: ذخیره داده‌های خام (OHLCV، شرکت‌ها، شاخص‌ها) و نتایج تحلیل‌ها
- **Backend API (FastAPI یا مشابه)**: ارائه REST API و WebSocket برای تحلیل تکنیکال، تشخیص الگو، پیش‌بینی ML و ابزارهای تحلیل
- **اسکریپت‌ها و ابزارها**: برای بررسی داده‌ها، اجرای pipeline تحلیل، تست و پوشش کد
- **Docker و Deployment**: اجرای سرویس در محیط‌های کانتینری و ابری

## جریان داده و ارتباط اجزا
1. داده‌های خام از منابع مختلف جمع‌آوری و در دیتابیس ذخیره می‌شوند.
2. سرویس تحلیل تکنیکال و ML داده‌ها را پردازش و نتایج را در جداول خروجی ذخیره می‌کند.
3. کاربران از طریق REST API یا WebSocket به نتایج تحلیل، سیگنال‌ها و ابزارها دسترسی دارند.

## یادگیری ماشین و تحلیل تکنیکال
- مدل‌های ML در مسیر `ml_models/` و اسکریپت‌های مرتبط در `examples/ml/` و `src/` قرار دارند.
- برای آموزش مدل‌ها از داده‌های `price_data` و سایر جداول استفاده می‌شود.
- الگوریتم‌های تحلیل تکنیکال (trend, momentum, volatility, pattern recognition) در `src/` و نتایج در جدول `historical_scores` ذخیره می‌شوند.
- برای تشخیص الگوها و سیگنال‌دهی، از API `/api/v1/patterns/detect` و `/api/v1/analyze` استفاده کنید.
- برای پیش‌بینی با ML، از `/api/v1/ml/predict` استفاده کنید.
- داده‌های ورودی مدل‌ها باید ساختار استاندارد (OHLCV + timestamp) داشته باشند.

### مثال جریان یادگیری ماشین:
1. استخراج داده از دیتابیس (`price_data`)
2. پیش‌پردازش و مهندسی ویژگی‌ها (feature engineering)
3. آموزش مدل (در `ml_models/` یا اسکریپت‌های `examples/ml/`)
4. ذخیره مدل و استفاده در API
5. ارزیابی و بهبود مدل با داده‌های جدید

## مهم‌ترین جداول دیتابیس
- **price_data**: داده‌های کندل (OHLCV)
- **companies, sectors, markets**: اطلاعات پایه شرکت‌ها و بازار
- **historical_scores**: نتایج تحلیل تکنیکال و ML (امتیاز، سیگنال، توصیه)

## API و WebSocket
- REST: `/api/v1/analyze`, `/api/v1/patterns/detect`, `/api/v1/ml/predict`, ...
- WebSocket: `ws://localhost:8000/ws/{client_id}` با انواع subscription (market_data, technical_analysis, ...)

## تست، توسعه و پوشش کد
- اجرای تست‌ها: از VSCode Tasks یا دستور `pytest tests/ -v` استفاده کنید.
- پوشش کد: `pytest --cov=src --cov-report=html`
- تنظیمات محیط: متغیرهای محیطی در انتهای فایل `database_connection_info.txt`
- تست مدل‌های ML: اسکریپت‌های تست در `tests/ml/` یا `tests/unit/` قرار می‌گیرند.

## conventions و نکات مهم
- ساختار پوشه‌ها: کد اصلی در `src/`، تست‌ها در `tests/`، مدل‌ها در `ml_models/`، اسکریپت‌ها در ریشه
- پایبندی به استانداردهای PEP8 و استفاده از type hints
- استفاده از Alembic برای migration دیتابیس
- مستندات و راهنماها در `docs/` و `README.md`
- برای توسعه الگوریتم‌های تحلیل تکنیکال، از الگوهای موجود در `src/` و مستندات `docs/` پیروی کنید.

## مثال پیام WebSocket
```json
{
  "message_type": "subscribe",
  "subscription_type": "market_data",
  "client_id": "unique-client-id",
  "timestamp": "2024-01-01T00:00:00Z",
  "data": {}
}
```

## منابع کلیدی
- `database_connection_info.txt`: ساختار دیتابیس و نمونه API
- `README.md`, `docs/`: راهنمای پروژه و معماری
- `src/`, `tests/`, `ml_models/`, `examples/ml/`: کد اصلی، تست‌ها و مدل‌های ML
